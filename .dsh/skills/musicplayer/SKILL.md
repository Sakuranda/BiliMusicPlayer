# BiliMusicPlayer 项目技能

先读根目录 `AGENTS.md`。代码架构与部署说明见 README / docs。

## 工作流

实现 → 有意义的后端 / 前端 / 安装回归 → Docker 构建与鉴权验证 → 更新文档和项目记忆 → 提交。发布先确认 VERSION 与标签相同，再推标签，由 Actions 创建 Release。公网安装与更新使用 `deploy/install.sh`，本地源码用 `deploy/deploy.sh`。不依赖任何作者私有服务器。

## 历史踩坑

- SQLite 独立线程连接 + WAL，迁移保留旧歌曲 ID 与关系；现有音频文件不能因脏状态重复下载。
- 多 P 的下载单位是歌曲 ID，旧记录补齐后重新选择；未核对的 P 不自动下载。
- 用共享下载队列和歌曲占用，文件 / 标签 / 歌词在同目录原子替换；音轨无损 remux 为 faststart，核对所选 CID 时长。
- Media Session 稳定 handler + 同步 ref，切歌不撤销上一曲元数据；解析器不盲猜切片 UP 为歌手。
- 2026-10-11 公开迁移只复制当前源码，不复制旧 Git 历史、数据、Cookie、env 或私人验收记录；Release 只打包跟踪文件并拒绝敏感路径。
- 2026-10-11 安装自动生成随机密码，Compose 显式 --env-file，不 source env；升级保留数据且构建后再查下载，数据库备份先于重启。
- 2026-10-11 管理员更新存密码摘要、轮换会话；TOTP 绑定先验证，登录验证 / 防重放同事务，服务器本地恢复保留曲库。
- 2026-10-11 相同参数重试不得重置配置，空数组需兼容 Bash nounset；CI 实跑全新 Compose 安装、升级保留、数据库备份与 Caddy 校验。

- 2026-10-11 曲库工具栏提供独立的顺序/随机播放入口，先同步播放器 mode ref 再启动同一筛选排序队列，避免状态更新滞后启动错误模式。歌词偏好上提至 PlayerContext，工具栏与展开页共享，不改 Audio 源/进度或 Media Session。刷新只读取曲库与归属，删除来源后复位筛选，捕获关系读取错误。

- 2026-10-11 海外机访问 B 站主 CDN 可能比备用 CDN 慢；用最多三主机的 128 KiB 有界 Range 测速和五分钟主机分数缓存选择地址，不提高 API 并发或保存签名 URL。不同端点临时目录隔离，下载/完整性失败继续备用地址；所有地址失败也把所选 CID 时长带到网页回退校验，避免接受短音频。

- 2026-10-11 把曲库刷新改为可等待的异步请求时，不能丢失原有会话检查；先读取账户状态，过期后返回登录，避免停留在无法恢复的 401 曲库。

- 2026-10-11 文件头 128 KiB 的热缓存速度不能代表整首音频；CDN 自动选择改为最多三个主机、第二个 1 MiB 的有界 Range 测量，五分钟缓存与冷探测锁保持，短文件416仅一次首段回落。200/异常范围不读全体，保持所选CID完整性检查。主备域名角色随playurl变化，只使用返回的原始签名地址，不硬编码“海外最快节点”。

- 2026-10-11 CDN 下载策略使用备用优先、主地址最后回退；只在多个备用主机间测速，单备用无需探测，主地址不得凭测速越过备用。调用排序函数时显式传入playurl主地址，只有backupUrl时不能误把首个备用认成主地址。

- 2026-10-11 已知 CID 可直接调用官方 WBI playurl，无需 view。旧播放接口成功时不额外请求；仅失败才获取/缓存公开 nav keys 并签名，匿名 nav -101 有有效 keys 仍可用。缓存/锁刷新与一分钟固定失败冷却避免额外请求风暴，沿用 Cookie/Referer/全局限速，错误不传播签名 URL 或 Cookie。WBI 与 CDN 网络提速是不同层次。
