## 1. 首次设置

打开 `https://music.example.com`，使用服务器部署时配置的管理员账户、密码和图片验证码登录。验证码点击图片即可刷新；同一 IP 在 10 分钟内连续失败 5 次会暂时锁定 15 分钟。

登录后进入左侧「**设置**」：

1. **API 地址**：用域名访问时留空即可（同源）；直连服务器则填 `http://127.0.0.1:8080`
2. 点「测试连接」出现 ✓ 即完成
3. 「登录与访问记录」会显示成功进入过的独立 IP 数、属地、登录时间、最近访问时间与分钟级活跃记录；这里也可以退出当前账户。系统不会把登录失败的密码或验证码写入记录

## 2. 导入收藏夹

1. 左侧「**导入收藏夹**」→ 粘贴链接；按需勾选「保存这个收藏夹」，还可开启「每天自动更新」→ 点「解析收藏夹」
2. **预览确认**：每首歌显示解析出的歌名、歌手、原标题、UP主、标签、**时长**
   - 解析不对的直接改输入框（歌名/歌手）
   - 多P视频见[第 4 节](#4-分p视频的处理)
   - 右上角可切换「紧凑 / 舒展」：紧凑模式一屏显示更多歌曲；舒展模式显示完整标签。每个 P 都独立列出并用复选框选择。偏好会保存在浏览器
3. 勾选要下载的歌（单P首次导入默认选中；多P按策略默认选择，手动策略先选首P供核对；已有音频默认不选）；不需要歌词时关闭右侧「自动匹配歌词」→「下载选中的 N 首」
4. 进度页实时显示每首状态（下载中/完成/失败），完成后点「前往曲库」

大收藏夹不会同时启动全部下载：歌曲先进入服务器的全局队列，默认同时处理 3 首，
其余显示“排队中”。即使同时启动多个收藏夹，整个服务的总并发也不会叠加超过配置上限（最多 5）。

### 保存与增量更新

- 勾选「**保存这个收藏夹**」后，链接会显示在导入页顶部，可随时点「手动更新」
- 「**每天自动更新**」按每个收藏夹上次检查时间计算，每满 24 小时自动检查一次；只下载缺失音频，不重下旧歌；手动策略的多P在导入页提示选择，之前明确不选的P不会偷偷下载
- 取消保存只移除链接和收藏夹归属，不会删除曲库中的歌曲、歌词或音频
- 保存后的收藏夹会出现在曲库顶部的「全部收藏夹」筛选框；收藏夹、歌单、歌手和关键词可以叠加筛选

### 链接从哪来

| 平台 | 位置 |
|---|---|
| 电脑浏览器 | 头像 → 我的收藏 → 点进收藏夹 → 复制地址栏链接（`space.bilibili.com/xxx/favlist?fid=xxx`） |
| 手机 App | 我的 → 收藏 → 收藏夹 → 打开目标收藏夹 → 右上角分享 → 复制链接（`b23.tv` 短链自动展开） |

支持的格式：`favlist?fid=`、`medialist/detail/ml`、`b23.tv` 短链。**「合集/列表」（`bilibili.com/list/ml...`）不是收藏夹**，暂不支持。

## 3. 私密收藏夹与 Cookie

未分享（私密）的收藏夹，B 站对匿名请求返回空数据，需要登录态 Cookie：

1. 导入页展开「**收藏夹是私密的？粘贴 B 站 Cookie**」
2. 获取 Cookie（浏览器已登录 B 站）：
   - **Chrome/Edge**：打开 bilibili.com → `F12` → 「网络(Network)」→ 刷新页面 → 点任意 `api.bilibili.com` 请求 → 「标头(Headers)」→ 复制 `Cookie:` 一行
   - **Safari**：设置 → 高级 → 勾选「显示网页开发者功能」→ 开发菜单 → 显示 Web 检查器 → 同上
   - 只需保证包含 `SESSDATA=...` 即可，整串粘贴也行
3. Cookie 会保存在当前浏览器（便于再次粘贴）和你的私人服务器（`data/cookies/`，文件权限 0600），仅用于访问 B 站；私密收藏夹的每日自动更新依赖服务器副本。过期（约 1~3 个月）后重新粘贴
4. 带 Cookie 时，解析与下载都会使用它（更稳定、音质更全）

## 4. 分P视频的处理

B 站视频可能包含多个分P（如歌回的每一P是一首歌）：

重复导入同一个收藏夹时，服务器会核对实际音频文件与已下载分P；已经存在的歌曲会自动跳过，即使旧任务曾中断或状态显示异常也不会重新下载。B 站详情接口临时受限时会保留上次确认过的分P信息。

- 每个 P 独立保存为歌曲，全部标题和时长都列出，支持复选框选择部分 P。
- 顶部快捷按钮「只下载首P」「下载全部」；也可取消全选，逐个勾选需要的 P。
- 导入页可设置新收藏夹默认策略：手动选择、只下载首P、下载全部。各已保存收藏夹也可单独设置；明确保存过的手动选择优先于默认策略。
- 每日或手动更新发现多P后，手动策略不立即下载这些 P；收藏夹行显示「N 个多P待选择」，下方自动展开全部多P视频与分P标题的长列表。每个视频都有「只下载首P」「下载全部」「取消全选」，也可逐P勾选。日更提示在导入页每 30 秒刷新。
- 旧记录已有多P信息时，启动后自动补齐所有P的歌曲记录，并同样提示重新选择。原有歌名、歌手、歌曲ID和音频保持原样，已下载的P始终跳过。
- 已处理的多P仍保留在展开列表中，可以重新选择；未选的P不会在后续日更自动下载，已有音频不会因取消勾选被删除。
- 选另一个 P 会新增另一首独立歌曲，不再覆盖当前歌曲的音频或改变它的源链接。

## 5. 曲库管理

- **视图**：曲库右上角可切换「卡片 / 列表」，也可用「封面」拨动开关统一显示或隐藏封面；视图和封面偏好会保存在当前浏览器
- **播放**：点卡片或列表行直接播放（点击队列中的其他歌会切歌）；只有点击歌曲封面才会同时打开**全屏封面 + 滚动歌词**。底部播放条仍可用右侧箭头展开，歌词行支持点击跳转
- **播放模式**：底部播放条左侧的模式按钮可在「列表循环 → 随机播放 → 单曲循环」之间切换，选择会保存在当前浏览器。随机播放会为当前队列生成一轮不重复的随机顺序，每轮结束后重新洗牌；随机模式下点击「播放全部」会立即重新洗牌并从随机歌曲开始，连续两次不会从同一首开始（曲库只有一首时除外）
- **系统媒体控制**：macOS 键盘/控制中心和 iPhone 锁屏的播放、暂停、上一曲、下一曲、进度拖动均会控制当前网页队列；系统正在播放区域会显示本曲歌名、歌手、专辑与封面，浏览器标签标题也会随歌曲更新。连续切歌时会保持同一个媒体会话，避免其他播放器在曲目间隙抢占“正在播放”区域
- **歌单**：顶部文件夹按钮可创建、重命名或删除歌单；歌曲右下角的列表加号可加入歌单。在某个歌单内再次打开该按钮，也可将歌曲移出当前歌单。歌单不复制音频，不额外占用媒体存储
- **收藏夹、歌单与搜索**：保存的 B 站收藏夹、歌单、歌手下拉框和关键词搜索可以叠加；「播放全部」只播放当前筛选出的歌曲
- **编辑**：卡片右下角或展开歌词页右上角 ✏️ → 修改歌名/歌手/专辑；同一弹窗可上传/替换/删除 `.lrc` 或 `.txt` 歌词。保存后数据库、同名 `.lrc` 和音频内嵌标签同步更新
- **封面**：编辑歌曲信息中点「重新下载歌曲封面」，刷新 B 站当前封面并同步到音频内嵌封面；不重新下载音频。失败保留原网页封面。
- **歌手分类**：点「按歌手分类」浏览歌手卡片，再点歌手查看和播放对应歌曲。可叠加收藏夹、歌单和搜索。
- **客户端歌手分类**：下载、改名和服务启动后自动生成 `歌手 · 名称` 歌单；也可点「同步歌手分类到客户端」。Navidrome 下一次扫描后，在 Amperfy 分别刷新播放列表和歌单内容即可浏览。无需复制音频。旧歌手已无歌曲时其分类会清空，可在客户端删除空歌单。
- **删除**：卡片右下角 🗑️ → 确认后删除音频、.lrc 歌词、封面与记录（不可撤销）
- **处理中/失败的条目**：曲库底部单独列出，可删除或等自动重试

## 6. 重复导入与去重

- 每首歌都保存了对应的 **B 站视频链接**（含分P参数），可在编辑弹窗「在B站打开视频」跳转
- 同一收藏夹再次导入：只对新增或缺失必要信息的条目请求详情，**已有实际音频且分P未明确变化的歌自动跳过**，即使旧任务状态曾变成 pending/error 也不会重复下载
- 只下载选择中缺少实际音频的P；不同P不会共用目标音频文件

## 7. 数据备份（CSV 导出）

「设置」→「**导出歌曲清单 CSV**」：包含 歌曲名/歌手/专辑/bvid/B站视频链接/分P/时长/状态/歌词来源，Excel 可直接打开（已处理中文编码）。

服务器端数据库位于 `/opt/musicplayer/data/musicplayer.db`（SQLite），完整备份方法见[部署运维](部署运维.md)。

## 8. iOS 播放（Amperfy）

1. App Store（国区）下载免费的 **Amperfy**（支持歌词/离线缓存/CarPlay）
2. 添加服务器 → 协议 **Subsonic**
3. 地址 `https://navi.example.com`，账号密码 = Navidrome 账号（首次访问 Navidrome 创建自己的账号）
4. 保持在线模式，进入「播放列表」下拉刷新，再打开「最近添加 · 新歌在前」并下拉刷新歌单内容。需要反向顺序时选择「最早添加 · 老歌在前」。两张歌单只引用音频，不复制文件，服务器扫描后会自动纳入新增歌曲，排除已丢失文件。
5. Amperfy 2.0 及以上也支持「歌曲 → 排序 → Date Added（添加时间）」；原生菜单按新到旧排列。时间是 Navidrome 首次扫描入库时间，不是 B 站发布时间，也不是添加进收藏夹的时间。
6. 「设置 → 播放器」中的 Cellular Streaming Format、WiFi Streaming Format 和 Cache Format 可分别选 **Raw**。本服务已提供标准 AAC/M4A，可直接播放，避免 AAC 再转 MP3。低流量需求仍可选 MP3 并限制码率；修改格式不会替换已缓存音频。

**为什么歌曲没有立即出现？** 网页下载完成 → Navidrome 检测文件（另有每分钟扫描兜底）→ Amperfy 在线刷新，本机才会显示。歌曲列表的增量刷新主要围绕新专辑；同一专辑追加歌曲可能没被取回，此时刷新上述歌单内容。离线模式只显示已缓存内容，不会实时获取服务器新歌。`.lrc` 和内嵌歌词由 Navidrome 提供，修改后同样需要扫描和 App 刷新。

**更新分三层：** 网页界面通过服务器部署更新；Amperfy 本体通过 App Store（测试版通过 TestFlight）更新；歌曲、封面和歌词通过 Navidrome/Subsonic 同步。App 不持续实时订阅网页，也不会因网页更新自动升级。已下载的旧音频需针对该曲重新下载才会替换，避免为了刷新一首歌清空整个缓存。网页歌单与播放队列未同步到 Navidrome，本文两张自动歌单由 Navidrome 独立维护。

上述菜单与同步行为已对照 [Amperfy v2.0 发布说明](https://github.com/BLeeEZ/amperfy/releases/tag/v2.0.0) 和 [v2.1.1 同步源码](https://github.com/BLeeEZ/amperfy/blob/v2.1.1/AmperfyKit/Api/AutoDownloadLibrarySyncer.swift) 核对。

## 9. 常见报错

| 提示 | 含义 | 处理 |
|---|---|---|
| `请求失败 (502)` | 服务器正在重启/部署的瞬间 | 曲库刷新等只读请求会自动重试；导入/删除等写操作请确认服务恢复后再点，避免重复任务 |
| `B 站返回空数据：…私密` | 收藏夹未分享，需要 Cookie | 按[第 3 节](#3-私密收藏夹与-cookie)粘贴 Cookie |
| `bad parameter or other API misuse` | B 站接口限流（批量下载时偶发） | 系统自动等待重试；最终仍失败会在任务结束后自动重试一轮 |
| `412 / 风控` | 服务器 IP 被 B 站临时风控 | 自动换指纹重试；持续失败等几分钟再点下载 |
| `下载失败（B 站风控，两条路线均已重试）` | 该视频当次确实下不了 | 查看失败条目，稍后重试或删除 |
| 歌词为空 | 翻唱曲目在歌词库查不到或导入时关闭了自动匹配 | 在歌曲编辑弹窗上传 `.lrc` / `.txt`，或改歌名后重新下载 |

### iPhone 锁屏播放

在 Safari 中登录并先点击播放，锁屏后通过系统音乐面板暂停/继续、上一曲/下一曲，进度条可拖动。系统上一曲始终切歌；网页上一曲在播放超过 3 秒时先回到本曲开头。系统不再注册播客式快进/快退动作，避免占用切歌按钮。系统面板的布局由 iOS 决定，网页不能完全复制原生 Apple Music。

随机模式每轮播放完整洗牌队列，轮末不连续重复。网络异常/异常提前结束会提示重试并保留当前歌曲，不会直接跳歌；重试尽量恢复原进度。刷新曲库暂时失败也不会卸载播放器。若旧歌曲仍提前结束，先由管理员运行历史音频封装修复。

移动端曲库采用双列封面；底栏直接提供上一曲、播放/暂停和下一曲，点击封面展开歌词与歌曲信息。新 Logo 同步到浏览器标签、登录页和 iPhone 主屏幕图标。可通过 Safari 分享菜单“添加到主屏幕”；需要网络连接，未提供离线缓存。重试提示会显示在播放器上方。

2026-09-10 更新：播放器会在换歌、恢复播放、前后台切换时重新声明系统切歌动作。如果 iOS/macOS 面板仍变成前后 15 秒，在「设置 → 锁屏与系统切歌」点击「恢复系统切歌按钮」。此操作不换歌、不重载音频、不改变进度。可在刷新网页前「导出播放诊断」，用于判断系统是否把切歌事件传给页面；诊断仅含本页最近 100 条事件、歌曲 ID、时间、前后台状态与浏览器版本，不包含登录凭据或媒体 URL。

## 歌名与演唱者核对（2026-09-12）

导入会综合标题、标签、简介和已确认的曲库歌手。UP 主仅作为上传者保存；视频写有“原唱/作词/作曲”不等于这段音频的演唱者。歌词式标题可从标签找歌名，冲突或弱证据会显示“待核对”。预览支持“仅看待核对”和展开识别依据，筛选不会改变已勾选的下载歌曲。

仅凭标题括号或剩余文字猜出的演唱者不会自动建立歌手分组；证据不足时先以“未知歌手”入库，在识别依据中保留候选供核对。“双女”“原创说唱”等制作标签不会直接当作歌手。确认名称后可在预览或歌曲编辑中保存。

已有歌曲可在“编辑歌曲信息”中点“重新识别歌名与演唱者”，查看建议后“填入建议”，核对并保存。保存会同步更新音频标签。手工确认的歌手可帮助后续切片在标题/tag中匹配同一演唱者，日更不会覆盖手工修改。歌名与演唱者相同也不自动删除视频：不同翻唱版本可能值得保留，音频仍按 BV/分P去重。

## 一个 Music Player 专辑，按 Songs / Artists 听歌

收藏夹是多人演唱的合辑。新版统一 `Album Artist=Various Artists`，每首歌的 `Artist` 保留实际演唱者；同名专辑因此不再按不同歌手拆开。不同专辑名称仍保持不同专辑。

已有音频需要执行带备份的标签修复，并让 Navidrome 全量扫描（步骤见部署运维）。Amperfy 中先打开并刷新 `Music Player` 专辑的歌曲，让客户端取得各首的演唱者；然后在 Artists 右上角的 Filter 选 **All**。单独刷新 Artists 不一定获取到所有合辑演唱者。Compose 已启用 `ND_SUBSONIC_ARTISTPARTICIPATIONS=true`，点进演唱者可看到其参与的合辑。

Songs 保留每首歌曲的演唱者。`Various Artists` 只用于专辑归组。此流程已核对 Navidrome 0.63.2 实际 API 与 Amperfy 2.1.1 源码；其他客户端版本界面可能不同。

播放中出现缓冲会显示提示；断流后可点“重试”，会尝试保留中断位置。手机展开页可正常滚动歌词，macOS 上 Escape 可收起展开页。
### 曲库排序

网页曲库筛选栏的「歌曲排序」提供名称正序/倒序、添加时间最新/最早在前，默认最新在前，选择会保存在当前浏览器。中文名称按拼音顺序，数字按自然顺序（例如 2 在 10 前）。添加时间指歌曲首次进入网页曲库的时间。排序可与收藏夹、歌单、歌手和搜索共同使用，卡片与列表顺序一致；点歌及「播放全部」使用当前结果顺序，随机模式仍按洗牌规则播放。单独切换排序不会打断当前播放或改动已有播放队列。
