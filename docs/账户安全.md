# 管理员账户与可选 2FA

## 初次登录与修改账户

一键安装默认生成 `admin` 和随机密码，保存于服务器安装目录的 `deploy/.env`（权限 0600）。浏览器进入自己的网页域名，输入账户、密码、图片验证码即可登录；默认不要求 2FA。

在「设置 → 管理员账户与 2FA」填写用户名、当前密码、新密码和确认密码，点「保存账户」。新密码至少 12 字，允许中文；新密码留空仅改用户名。修改后保留当前浏览器会话，其他浏览器的旧会话失效。更改的账户保存在数据库中，密码使用带随机盐的 PBKDF2-SHA256（600,000 次）摘要；升级不重置。初始 `.env` 密码随后不再作为登录密码，编辑它也不会覆盖数据库账户。

## 开启 2FA（可选）

1. 输入当前密码，点击「设置 2FA」。
2. 使用支持 TOTP 的验证器扫描二维码，也可手动输入页面显示的密钥，类型选「基于时间」。二维码由本服务器生成，不发送到第三方二维码服务。
3. 输入验证器当前 6 位动态验证码，点击「验证并开启 2FA」。绑定 10 分钟内有效；验证成功前不启用，取消绑定保持关闭。
4. 此后网页登录需要用户名、密码、图片验证码及动态验证码。服务器与手机需自动校时；同一组已验证的动态码不能再次使用，连续操作请等待下一组。

开启 / 关闭 2FA 会使其他浏览器会话失效。要关闭，输入当前密码和当前动态验证码，点「关闭 2FA」。如需更换验证器，先关闭再重新绑定。

2FA 只作用于 BiliMusicPlayer 网页登录；Navidrome / Amperfy 使用独立账户。`API_TOKEN` 是独立的脚本访问凭据，默认不生成；设置后不会要求动态验证码，勿把它分享出去。修改账户和 2FA 接口要求管理员浏览器会话，不能仅靠 API_TOKEN 调用。

## 忘记密码或丢失验证器

必须能够登录自己的服务器（没有公开找回接口）：

```bash
cd /opt/bilimusicplayer
sudo docker compose --env-file deploy/.env exec api python -m scripts.reset_admin
```

按提示输入新的用户名和密码。重置会关闭 2FA、撤销所有网页会话，保留歌曲、收藏夹、歌单、音频和 Navidrome 账户。整个输入过程不显示或打印密码。

备份中的数据库包含账户摘要和验证器密钥，`deploy/.env` 包含初始密码及签名密钥，B 站 Cookie 也保存在 `data/cookies/`。部署目录和备份只供服务器管理员访问，不提交、不打包进公开 Release。
