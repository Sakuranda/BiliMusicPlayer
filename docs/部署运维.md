# 服务器部署与运维

## 一键安装（没有 Docker 也可以）

准备一台 Linux 服务器（推荐 Ubuntu 22.04/24.04 或 Debian 12，2 核 / 2 GB 起步，音频另留磁盘空间），以 root 登录或使用 sudo。需要 curl、tar、openssl、sha256sum；不需要 Python、Node 或 Git。

1. 给服务器绑定两个子域名，例如 `music.example.com`（网页）和 `navi.example.com`（Amperfy / Navidrome），把它们的 DNS A 记录指向服务器公网 IP。如配置了 AAAA，IPv6 也需可达。
2. 放行服务器及云平台防火墙的 TCP 80、443（UDP 443 可选）。这些端口应空闲；已有反向代理时看下方专用方案。
3. 把命令里的两个域名换成自己的，在服务器执行：

```bash
curl -fsSL https://github.com/Sakuranda/BiliMusicPlayer/releases/latest/download/install.sh | sudo bash -s -- --domain music.example.com --navidrome-domain navi.example.com --install-docker
```

如果已经是 root，去掉 `sudo`。脚本检测 Docker Engine 和 Compose v2，缺失时使用 [Docker 官方安装脚本](https://docs.docker.com/engine/install/ubuntu/#install-using-the-convenience-script)；已有环境直接使用。自动安装 Docker 适合新建服务器，有特殊运维要求的服务器可先按官方文档安装 Docker，再执行同一条命令。

安装器下载最新正式 Release、校验 SHA-256，然后使用 Docker 构建前端和后端并启动 API、Navidrome、Caddy。首次构建需要几分钟及联网下载依赖。Caddy 自动申请和续期 HTTPS 证书；域名及端口要求见 [Caddy 官方文档](https://caddyserver.com/docs/quick-starts/https)。发布包含完整源码，x86_64 / ARM64 服务器都由各自的 Docker 构建，不依赖作者的私人镜像或服务器。

默认安装路径 `/opt/bilimusicplayer`。脚本不会输出密码，初始网页账户为 `admin`，密码在该服务器的配置文件中：

```bash
sudo cat /opt/bilimusicplayer/deploy/.env
```

打开自己的网页域名，输入初始账户、密码和图片验证码。随后在「设置 → 管理员账户与 2FA」改成自己的用户名和密码。2FA 默认关闭，开启方法见 [账户安全](账户安全.md)。Navidrome 有独立账户：首次打开 `https://navi.example.com` 创建管理员，之后用该账户连接 Amperfy；网页账户的修改不会更改 Navidrome 账户。

指定目录或版本：

```bash
curl -fsSL https://github.com/Sakuranda/BiliMusicPlayer/releases/latest/download/install.sh | sudo bash -s -- --dir /srv/bilimusicplayer --version v1.0.0 --domain music.example.com --navidrome-domain navi.example.com --install-docker
```

Fork 使用 `--repo 你的用户名/BiliMusicPlayer`，先按 [发布教程](发布Release.md) 生成自己的 Release。

## 已有 Nginx / Caddy / 宝塔反向代理

保留现有代理，让安装器跳过内置 Caddy：

```bash
curl -fsSL https://github.com/Sakuranda/BiliMusicPlayer/releases/latest/download/install.sh | sudo bash -s -- --domain music.example.com --navidrome-domain navi.example.com --install-docker --no-https
```

给两个域名分别配置 HTTPS 反向代理到 `http://127.0.0.1:8080` 和 `http://127.0.0.1:4533`。API、Navidrome 默认只监听本机回环，公网不开放 8080 / 4533。代理应转发 `Host`、`X-Forwarded-Proto` 和真实客户端 `X-Forwarded-For`；启用 HTTP Range 支持，避免音频缓冲被代理截断。不要仅使用 HTTP 传输账户或 Cookie。

## 手动部署源码

```bash
git clone https://github.com/Sakuranda/BiliMusicPlayer.git
cd BiliMusicPlayer
sudo bash deploy/deploy.sh --domain music.example.com --navidrome-domain navi.example.com --install-docker
```

先生成配置但不启动：加 `--configure-only`，然后编辑 `deploy/.env`，最后运行 `sudo bash deploy/deploy.sh`。所有人工 Compose 命令都须加 `--env-file deploy/.env`，以便域名、端口及 HTTPS 模式参与变量替换。修改账户后，数据库中的账户设置优先于初始环境变量。

## 升级

```bash
curl -fsSL https://github.com/Sakuranda/BiliMusicPlayer/releases/latest/download/install.sh | sudo bash -s -- --dir /opt/bilimusicplayer
```

升级时不再传首次安装的域名参数。配置与 `data/` 保留，密码和 2FA 设置不会重置。运行中的下载会阻止升级；等待下载结束后再试。脚本构建完成后再次检查下载状态，并在容器重建前用 SQLite 在线备份保存曲库数据库到 `data/backups/pre-upgrade-*.db`。

升级前建议创建下面的完整备份。降级涉及数据库格式时，应同时恢复同版本备份；仅改镜像或回退源码不保证兼容新数据库。

## 备份与恢复

完整备份会短暂停止服务，备份音频、封面、歌词、Cookie、曲库、Navidrome 数据、证书及配置，结束时自动恢复服务：

```bash
cd /opt/bilimusicplayer
sudo bash deploy/backup.sh
```

文件保存在 `backups/full-日期.tar.gz`，权限由私密 umask 限制。此文件包含密码和 B 站 Cookie，不可上传到公开仓库。

恢复到同版本安装目录（先解压匹配的 Release，再复制备份）：

```bash
cd /opt/bilimusicplayer
sudo docker compose --env-file deploy/.env down
sudo tar -xzf /安全备份路径/full-日期.tar.gz -C /opt/bilimusicplayer
sudo bash deploy/deploy.sh
```

CSV 只备份歌曲清单，不包含音频和账户设置，不能代替完整备份。

## 日常维护

```bash
cd /opt/bilimusicplayer
sudo docker compose --env-file deploy/.env ps
sudo docker compose --env-file deploy/.env logs --tail 100 api
sudo docker compose --env-file deploy/.env logs --tail 100 caddy
sudo docker compose --env-file deploy/.env restart navidrome
```

配置项在 `deploy/.env.example`：下载线程默认 3（上限 5）、元数据线程 4、B 站请求间隔 0.5 秒；API / Navidrome 本机端口可调。用 `deploy/deploy.sh` 应用修改，会检查下载状态。`API_TOKEN` 默认留空；手动设置后，它是可绕过网页登录和 2FA 的脚本凭据，请只保存在服务器或密码管理器中。

如果是手动启动 Compose，必须先 `mkdir -p data/music/MusicPlayer-Playlists`，避免只读父目录内嵌套挂载失败。

## 部署验证和常见故障

- 安装器检查 API 健康、网页鉴权启用、匿名曲库返回 401；HTTPS 模式还检查公网健康地址。成功启动容器不等同于 DNS / 证书已就绪。
- 浏览器登录，导入自己的收藏夹，下载一首并试听、核对歌词和封面；多 P 检查所选标题及音频时长；Amperfy 连接自己的 Navidrome 域名再同步。B 站的真实下载依赖部署 IP / Cookie，构建测试不能保证服务端不会被风控。
- HTTPS 未就绪：确认 A / AAAA、80 / 443、现有端口占用及 Caddy 日志。脚本会失败并说明容器已启动；修复后在安装目录运行 `sudo bash deploy/deploy.sh`。
- Docker 安装失败：检查系统是否属于 Docker 官方支持发行版、软件源和网络。不要混装系统旧版 `docker-compose`。
- 构建无法访问依赖源：服务器需访问 GitHub Releases、Docker Hub、npm 与 PyPI。配置自己的可信镜像 / 网络后重试；脚本不会擅自替换第三方源。
- 412 / CDN 错误：查看歌曲错误和 API 日志，减少并发、更新 Cookie 后重试；不要以循环快速重试加重限流。
- 忘记密码或丢失验证器：按 [账户安全](账户安全.md) 中的服务器本地恢复命令重置，音频和曲库保留。
